# 长任务上下文改造与验收

发布目标：fork 的 `codex/reliable-task-context` 分支及该分支的可安装测试包。A 是关闭新策略时当前 Mika 的行为。冻结起始条件、模型、日期、候选与路线；真实订单仅用于用户最终验收，不用于开发回放。

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 计量 | 对照运行期总调用、HTTP 尝试、输入/缓存/输出、费用和结果；区分缺报与零。 | 新旧导出均可比较，不双算缓存或旁路；失败任务计入分母和总支出。 |
| 2 确定性视图 | 旧工具结果、窗口历史和截图与完整证据分开；通过实际读取校验来源，保留用户约束、证据字段、依赖基准、工具配对及模型私有信息。 | 无人工标注的跨 App 酒店、30/100 步及短任务对照；不存在、冲突、过期或超预算不得导致错误选择。 |
| 3 任务记忆与交接 | 有来源/版本的事实与任务状态，处理纠正、进度与终止条件、证据读取和持久化断点。 | 新指令先于下一决策生效，未知外部动作先查结果；中断、重启、并发/写失败不丢已提交数据、不重发未知动作。 |
| 4 可选增量摘要 | 分块、增量、去重、事务性提交；独立无工具的轻量模型优先，计入运行预算，失败时保留确定性视图。 | 模型异常、版本冲突、取消、模型切换、合并均有对照；未经非劣验证不默认开启语义压缩。 |
| 5 发布 | 核查成本、前缀与可靠性，生成便于 A/B 的构建与复测说明，仅推送 fork。 | 相关 JVM、协议前缀、Android 构建、项目检查；校验远端分支、提交和 APK。实机服务商用量与订单由用户最后独立验收。 |

实际成功口径：按好评排序取前三家非民宿，三家到同一终点均用步行路线，预订对象与最近者一致，回复含正确地点、价格和时间。缺任何候选的路线不能宣称已确定最近者。测试中的结构校验不等同真实模型成功率。
