# 截图回放必须保存实际动作的帧关联

## 信号与原因

Mika 的旧 `Media` 事件只给出步号和截图编号，同一循环轮次可以包含多个批次或脚本子动作。
`ModelReply` 是计划，不能据此把坐标画到同一步的任意截图上；有些画面是操作后状态。
工具坐标为 0–999，运行截图会压缩到宽度不超过 720 像素，不能直接使用原始设备像素位置。

## 处理与边界

- 在实际界面动作入口采集操作前帧；操作后复用本次调用已有的图像，否则在权限/防截屏核对后采集。
- 用 `RunEvent.TaskPlayback` 的 `callId`、`beforeId`、`afterId` 明确关联动作，不靠时间接近或步号猜测。
- 标记只出现在前帧；回放不生成未采集的空帧；真实缺文件跳过并提示数量，不拿前帧冒充后帧。异步加载后将图像与其自身标记作为一个状态交叉淡入，避免新标记叠在旧图上。
- 元素目标的中心先按原始屏幕宽高归一化；绘制时按实际显示图片的尺寸映射。
- 语义滚动不保证真实触点，箭头必须标为方向示意。旧记录仅展示画面，不编造标记。
- 本地记录图像不加入模型图片列表或上下文；记录数量增加仍可能增加截图延迟和磁盘占用，不能把“不增加模型图片”解释为零开销。

## 真机反馈修正（2026-11-05）

验证状态：在一台 PKX110 手机上核对一次。任务记录中的 34 张已登记截图全部存在；两处 beforeId 为 null（启动与一次返回），旧界面把它们生成为空白帧，误报“未保存或已清理”。这不能推断所有缺图都不是落盘问题：实际文件缺失仍需单独检查。

处理：先区分“从未采集”“文件不存在”“解码失败”，只将实际可用帧放入连续播放序列。缺帧标记不得转移到结果帧。不要为了消除提示而改大队列、补造截图或从别的动作借帧。

关键页不等于均匀抽样的动作：通过 Observed.id → Activity.obsIds/callId → TaskPlayback.callId 建立关联，优先选报告正文实际引用的页面文字，按标题去重；没有证据时只使用“结束时页面”。同一轮多个子动作仍不得按轮次合并。导航只展示重要阶段；后续用户反馈明确取消明细入口，原运行时间线仍可查看。

回放画面必须与控件共用受约束的可用高度，画面按宽高比 fit，不能把整屏放进同一个长滚动列表。默认 2.4 秒停留从图片解码完成后开始；手动与自动使用同一路径，360 ms 过渡绑定图片和标记。布局、红圈、方向箭头、倍速、明细及实际导出流程已通过 ADB 真机检查；Compose 自动化因设备 InputManager.getInstance 缺失受阻，不能记为通过。

相关验收：[真机反馈修复](../../dev/2026-11-05_report-replay-phone-fixes.md)。

## 重复动作项与错误关联（2026-11-05，preview.3）

信号：点击/滑动有时“没有标记”，实际 trace 坐标完整。原因是前后帧展平后共享同一动作标题，后帧按正确规则不画原图坐标，却看起来像漏标记的另一次操作。应先核对播放项语义，再排查采集遗漏。

当时处理（下节已确认有遗漏，不应作为推荐规则）：一个动作优先展示它带标记的原帧，无标记动作选可用结果帧；最后一张不同的结果另标“结束时页面”。不能为覆盖率把原坐标搬到结果图。原始结果帧仍用于报告关键页。真机原任务由 22 张播放帧变成 12 操作 + 1 结束页面，点击红圈、滚动箭头和具体失败提示均核对一次。

失败原因通过 TaskPlayback 的 step/tool/callId 匹配 ToolResult，再复用时间线译名；邻近轮次或批次子操作不能借用错误原因。未知错误使用脱敏 message 或错误码，无记录就明确说明。`TaskPlaybackActionsTest` 覆盖同轮相邻调用、跨轮同 callId、缺原帧、旧记录及截断错误；1,492 项 Android 单测通过。设备 Compose 框架限制仍存在，不等于 UI 自动化通过。

完整验收：[操作标记与错误修复](../../dev/2026-11-05_replay-markers-and-errors.md)。

## 反例：点击详情后立即返回丢失中间页面（2026-11-05）

状态：本地 trace、此前导出的截图文件清单及当前代码已确认；尚未修复，未连接手机重新验证。用户要求本轮只分析讨论。

Preview3 的 `actionFrames` 每动作只选一张图：有标记的点击选 before，没有标记的返回选 after。若点击打开详情后下一动作是返回，两者都选中了列表，点击 after 和返回 before 中的详情页被一起排除。只追加全任务的最终结果不能补救中间结果。相同规则还使关键页/阶段入口落到打开详情前的列表。此前“一个动作一张图”的经验有缺陷，需要撤销；保留原始截图不能保证回放覆盖实际页面。

诊断证据：同一历史任务中第 8、9 次动作分别登记 before/after；当前筛选明确跳过两张中间记录。点击后的 Observed 含详情标题和正文，截图文件清单含两张中间图。用户截图对应相邻列表画面。这能确认播放筛选缺陷，但不代表已核对手机当前文件状态或每张截图的实际像素内容。

建议方向（待讨论实施）：保留动作提示及结果画面的时间顺序，取消前后切换按钮不等于删除结果帧；在一个动作内部展示标记再过渡到结果。关键页入口应到证据图。若要合并相邻重复画面，需要图像相同的证据，不能按是否有标记取舍。补充“点击打开详情→立即返回”的页面覆盖测试；现有 `TaskPlaybackActionsTest.eachGestureKeepsItsOwnAnnotatedFrameAndFinalResultIsDistinct` 只断言筛选结果，未检查中间页面完整性，不能证明此需求正确。
